1. Purpose

P5.2 establishes the runtime and framework baseline for GeoField Frontend.

The purpose of this document is to distinguish explicitly between:

- Technology Selected
- Technology Installed
- Technology Detected
- Technology Runtime-Verified
- Technology Deferred

A technology must not be marked as verified merely because an installer, executable, SDK directory, or package exists.

---

2. Frontend Runtime Architecture

GeoField Frontend has two primary execution targets:

                         GeoField Frontend
                                |
                 +--------------+--------------+
                 |                             |
               Mobile                         Web
                 |                             |
              Flutter                    React + Next.js
                 |                             |
               Dart                    TypeScript + Node.js
                 |
              Android

Mobile

Mobile is:

- field-first
- action-first
- location-first
- offline-first

Web

Web is:

- management-first
- analysis-first
- map-first
- information-dense

Mobile and Web are therefore separate platform implementations sharing product semantics, contracts, design tokens, and backend contracts where appropriate.

30. Deferred Technology Decisions

The following technologies intentionally remain unfrozen.

State Management

No state management package is permanently selected in P5.2.

Reason:

State ownership must first be derived from actual application boundaries and backend contracts.

---

Local Storage

No final local persistence library is frozen.

Reason:

GeoField is offline-first, therefore storage selection must consider:

- offline drafts
- sync queue
- attachments
- migrations
- idempotency
- crash recovery
- encryption requirements
- lifecycle durability

---

API Client

No specific generated/manual client library is frozen.

Reason:

The API client must be selected after the backend contract and Web/Mobile workspace boundaries are established.

---

Map Engine

Map engine remains explicitly unfrozen.

Selection criteria remain:

- Offline capability
- Raster / Vector support
- Mobile + Web compatibility
- Performance
- Licensing
- Self-hosting
- Global availability
- CRS support
- PostGIS compatibility
- 3D capability where required

Map Engine must not be frozen solely because a convenient library is available.

---

3D

Three.js / React Three Fiber remain optional.

They are not part of the mandatory P5.2 baseline.

---

Animation

Rive remains optional.

It is not part of the mandatory P5.2 baseline.

32. Important Versioning Rule

This document must distinguish:

Technology Baseline

from:

Actual Installed Version

and:

Runtime Verified Version

For example:

Node.js
Baseline = 24.x LTS
Actual = 24.20.0
Verified = YES

whereas:

Next.js
Baseline = 16.x
Actual = NOT YET INSTALLED
Verified = NO

This prevents the repository documentation from claiming verification for software that has only been selected architecturally.

The same rule applies to Android components:

Android Platform
Available = API 35 / API 36
Toolchain = VERIFIED
Physical Runtime = VERIFIED

but:

Emulator graphics runtime
Environment-limited

The successful physical-device test is the authoritative Android runtime proof.
